# 创建 Skill（生产级指南）

创建一个符合 shenlan 规范的技能目录与 SKILL.md：先确认需求，再检查命名与放置位置，按模板编写，最后读回自检。

## 目标

产出一个可被 shenlan 自动扫描、按需加载的技能：

- 一个目录 `<skill-name>/`，内含必需的 `SKILL.md`
- frontmatter 合法，`description` 含触发关键词
- 命名不与任何已安装技能冲突，放置位置符合用户意图（项目级或用户级）
- 创建后逐项自检通过，并向用户说明位置与用法

## 触发条件

- 用户说"创建/新建/写一个 skill（技能）"、要 skill 模板，或要求把某类可复用流程（文档规范、检查清单、工具用法、发布流程）固化为技能
- 用户要求更新已有技能（沿用本指南的模板与自检部分）
- 用户问技能应该放项目级还是用户级

## 执行步骤

### 1. 先确认需求（一次只问一个）

逐个确认，不要一次性抛出多个问题：

1. skill 名称与用途（做什么）
2. 触发场景（什么情况下应该使用）
3. 放置位置（项目内共享还是个人通用；用户不确定时给出建议）

### 2. 命名规范检查

- 小写 kebab-case：只允许小写字母、数字、连字符（如 `weekly-report`、`deploy-check`）
- 长度 ≤ 40 字符
- 与已安装技能不重名：先列出已安装技能（`shenlan skills list` 或 `/skills`）核对；**内置技能 🔒 不可覆盖、不可修改**，重名时必须改名

### 3. 放置决策

- **项目级**：`.shenlan/skills/<skill-name>/SKILL.md` —— 随仓库提交，团队共享
- **用户级**：`~/.config/shenlan/skills/<skill-name>/SKILL.md`（本机所有项目可用），或 `config.skills` 中指定的自定义目录

判断依据：只服务当前项目/团队 → 项目级；个人跨项目通用流程 → 用户级。

### 4. 按模板编写 SKILL.md

```markdown
---
name: <小写-kebab-case，≤40 字符，与目录名一致>
description: <一句话，必须包含触发关键词，说明何时使用>
---

# <标题>

## 目标
<该技能要达成的结果>

## 触发条件
<何时应使用；列出关键词或场景>

## 执行步骤
<按顺序的明确步骤，必要时分小节>

## 输入与输出
<需要的输入（路径/参数/材料）与产出物>
```

编写要求：

- frontmatter 必填 `name`、`description`；`name` 必须与目录名一致；`description` 必须包含触发关键词（AI 依据它决定何时触发）
- 正文按 目标 / 触发条件 / 执行步骤 / 输入输出 组织，先概览后细节（渐进式披露：SKILL.md 先给结论与流程，长文档放 `references/` 按需引用，不要整篇内联）
- 复杂技能可增加目录结构：
  - `references/`：按需引用的补充文档
  - `scripts/`：可执行脚本（调用仍走权限门，不豁免用户确认）
  - `assets/`：模板、图片等静态资源
- 技能不豁免权限门——脚本执行、文件写入仍需用户确认

### 5. 创建文件并读回自检

创建目录与 `SKILL.md` 后逐项验证：

1. frontmatter 可解析：读回文件，确认 `---` 包裹且 `name`/`description` 字段齐全
2. `description` 含触发关键词
3. 与已安装技能无重名（内置 🔒 不可覆盖）
4. 路径正确：`<技能目录>/SKILL.md` 存在，目录名与 `name` 一致
5. 内容完整：读回正文确认无截断、无残缺

全部通过后告知用户：

- skill 所在路径
- 用法：输入 `$<skill-name>` 或自然语言触发（模型按 `description` 匹配）
- 可用性：技能创建后可在 `/skills` 面板查看，新会话与当前会话均可按 `description` 触发
